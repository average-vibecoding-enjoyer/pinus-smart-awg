# Pinus Smart AWG 3.3.0 Preview

Отдельная Windows x64 сборка на базе исходников 3.2.5 (`28f6f8436ec1a649d66bceacfb210b0cec9827ad`). Основная установленная версия и её подключение не обновлялись. Исходники, службы, пути данных, окно и идентификаторы MSI у Preview отдельные.

## Что изменено

- AWG 3.1 в нативном и выборочном режимах: HeaderProtectionKey, ContentPaddingAddition, диапазоны таймеров и PersistentKeepalive, RandomTrailers, DisableCookies. Старые WireGuard/AWG 1.x–2.x конфиги сохраняют параметры; новые опции им не добавляются. Обычные `.conf` и ZIP с конфигами остаются форматом импорта. Контейнеры `vpn://`/Amnezia JSON сюда не относятся.
- Официальное ядро `amneziawg-go/v3 v3.1.20260828` закреплено по commit и контрольным суммам. В локальной копии исправлены потеря первого пакета при смене S4 во время ожидания TUN Read и приём отрицательных/слишком больших CPS-длин. Патч и полный соответствующий исходный код включены.
- В «Весь интернет» видны VK и «Белые списки», оба изначально включены. В «Только выбранное» дополнительно доступны прежние сервисы, VK и российская группа изначально выключены. В обоих режимах включено = VPN, выключено = напрямую. Выбор хранится отдельно для каждого режима.
- Приоритет: пользовательские правила → VK → российская группа → локальная сеть → выбранные сервисы → общий маршрут. Согласованные доменные DNS-правила: прямые исключения используют резолвер физической сети, остальные запросы идут через AWG.
- «Фиксировать подключение» включено изначально: выбор профиля и изменения маршрутов сохраняются; применение — отдельная кнопка. Изменение активного конфига хранится отдельно с DPAPI до применения. Активный профиль подписан отдельно от сохранённой маршрутизации.
- Объяснение ожидаемого маршрута с конфликтующими правилами; просмотр применённых настроек; поиск профилей/правил Ctrl+F; клавиатурная навигация основного окна; прокрутка сервисов и инструментов; обновлённые встроенные и закреплённые подписанные пресеты.
- Последние 12 версий маршрутизации; восстановление; дублирование; зашифрованная резервная копия профилей и настроек маршрутизации (AES-256-GCM + scrypt). Восстановление создаёт новые профили и не запускает их. Пароль минимум 12 символов. История, временные несохранённые изменения редактора и ожидающая применения версия самого конфига не включаются в эту копию.
- Защита при сбое: явная настройка «блокировать весь интернет при отказе Preview». Фильтры WFP принадлежат только Preview; постоянная блокировка сохраняется при падении процесса, а разрешение TUN пересоздаётся по текущему интерфейсу. Есть команда снятия блокировки и кнопка остановки. Отдельный режим защиты только выбранных приложений не заявлен.
- Резервные профили: конечный проход по явно выбранному списку при сбое запуска/процесса и восстановлении. Это не проверка доступности удалённого сервера и не автоматический поиск быстрого сервера.
- Диагностика: наличие туннеля отделено от результата трафика. По отдельной кнопке нативный режим показывает handshake/счётчики; Smart выполняет ограниченные HTTPS-пробы IPv4, IPv6 и DNS через отдельный локальный SOCKS-вход с одноразовым паролем и обязательным маршрутом AWG. Копируемый краткий отчёт исключает имена профилей, endpoint, пути и свободные тексты ошибок.
- Импорт по одноразовой HTTPS-ссылке: предварительное подтверждение сервера, просмотр профиля, импорт новой копии без запуска. Команды PreUp/PostUp/PreDown/PostDown при таком импорте запрещены. Серверный модуль и патч интеграции бота подготовлены в `server-preview`; на действующем сервере они не устанавливались.

## Исправления по аудиту

Исправлены разбор ошибочного CIDR и IPv6 endpoint, дедупликация AllowedIPs, гонки callback-реестров, таймеров suspend/resume и восстановления, фиксация LUID только после успешной привязки сокета, отложенные повторы смены физического интерфейса, ошибочный повторный запуск при изменении профиля, потеря частичных результатов импорта, утечки дескрипторов и ошибки чтения WinHTTP/ringlogger. Очередь событий интерфейса ограничена; уведомления отправляются последовательно. Ожидание удаления службы ограничено временем; обновление сначала подготавливает файлы, потом останавливает свою службу. Обработаны откаты после неудачного переключения. Старый несовместимый автоматический updater отключён. Уменьшена частота фоновых перерисовок неподвижного окна.

Для проверки JSON перед переключением добавлена команда движка `pinus-check`. Она выполняет типизированный разбор и проверку AWG-параметров, не создавая box/TUN/слушатель и не выполняя DNS-запрос. Полная проверка работоспособности конфигурации остаётся этапом запуска.

## Что проверено локально

- Тесты клиента и Windows core; `go vet` с прежними исключениями для WinAPI-композитов и unsafe-преобразований.
- Обмен настоящими зашифрованными пакетами двух экземпляров ядра **только в памяти**, в обе стороны: WireGuard, AWG 1.x и AWG 2.x между новым ядром и прежним `v0.2.18`; AWG 3.1 между двумя новыми ядрами. Сокеты, драйверы и сетевые адаптеры в этих тестах не создаются.
- Разбор, сохранение и UAPI/JSON-передача новых полей; сохранение старых параметров; отклонение опасных диапазонов и CPS; шифрование/ошибочный пароль/подмена резервной копии; приоритеты маршрутов и DNS; ограничения импорта и одноразовых токенов; единственный победитель среди одновременных запросов токена.
- Итоговый движок принял девять синтетических конфигураций через `pinus-check`: восемь сочетаний режима/VK/российской группы и отдельную конфигурацию AWG 3.1.
- Source govulncheck клиента/движка и binary govulncheck не обнаруживают достижимых известных уязвимых функций. В `x/crypto` остаётся предупреждение уровня модуля о неиспользуемом OpenPGP. Символы Preview-бинарников сохранены для проверок и диагностики.

## Граница проверки

Настоящие AWG 3.1 серверы, скорость, задержка, смена Wi-Fi, сон Windows, фильтры WFP при падении процесса, установка/обновление MSI и реальные звонки/стриминг VK на этом компьютере не проверялись. Клиентские тесты не доказывают, что сервер уже поддерживает AWG 3.1. Новые серверные параметры нужно согласовать отдельно на тестовом сервере.

Preview отказывается подключаться и восстанавливать туннель, пока работает другая служба Pinus. Для полноценной сетевой проверки используйте отдельную Windows VM/компьютер и отдельный тестовый профиль. Это тестовая сборка, а не подтверждённая замена рабочей 3.2.5.

VK: домены `.ru` и `.com`, CDN фото/музыки/видео и служебные узлы звонков включены по публичным страницам, JS и TLS-сертификатам. Авторизованные сеансы воспроизведения и звонков не перехватывались. Сторонний DoH/ECH может скрыть домен; WebRTC по неизвестному прямому IP в браузере нельзя надёжно отнести к VK без чрезмерно широкого обхода. Для отдельного приложения звонков есть правила EXE. Список российских сервисов конечный, а не весь `.ru`, все ASN или гарантия работы мобильного «белого списка» оператора.

TLS/TCP резервный транспорт и собственная экспериментальная маскировка не добавлялись. Изменений сервера и действующих профилей нет.

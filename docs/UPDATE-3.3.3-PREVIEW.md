# Pinus Smart AWG 3.3.3 Preview

Исправление отказа TCP-соединений при недоступном IPv6 внутри VPN. В 3.3.2 на рабочем подключении Google трижды открывался по IPv4 (HTTP 204), а три обычных и три IPv6-запроса завершались `ERR_CONNECTION_RESET`. В журнале движка этим отказам соответствовало `connect tcp [IPv6]:443: network is unreachable`. Процесс движка оставался прежним. Это отдельный сбой от DNS прямых соединений, исправленного в 3.3.2.

Когда IPv6-подключение через AWG возвращает именно ошибку недоступности сети, новый движок использует известное имя сайта для получения IPv4-адреса через DNS того же VPN и повторяет TCP-подключение через AWG. Уже установленное соединение и его данные повторно не отправляются. Рабочий IPv6 продолжает использоваться обычным способом.

Повтор разрешён только для профиля с IPv4, TCP-соединения и корректного имени сайта. Отменённый запрос, неизвестное имя, отсутствие IPv4-ответа, ошибки TLS, сброс уже установленного соединения и UDP не превращаются в такой повтор. Прямые исключения VK и российских сервисов выбираются до AWG и сохраняют прежнее поведение. Перехода VPN-трафика на прямой интернет нет.

## Проверка

Тесты исправления используют производственный код подключения с DNS и конечными соединениями в памяти; создание TUN, служб и сокетов ОС не требуется. Отрицательный контроль воспроизводит отсутствие повтора в прежнем поведении. Точные результаты находятся в `evidence/routefix-ipv6-tests.txt`, `evidence/routefix-ipv6-negative.txt` и `evidence/routefix-engine-tests.txt`. Проверки клиента, `go vet`, синтетических конфигураций и метаданных MSI сохраняются рядом.

Движок и клиент пересобираются вместе. Изменение движка включено в проверяемый патч к закреплённой исходной ревизии; соответствующие исходники поставляются отдельным архивом. AWG 3.1 и старые конфиги сохраняются; Wintun берётся из прежней проверенной сборки.

## Границы результата

Эта сборка подготовлена отдельно и автоматически не установлена. Исправление ещё нужно проверить в браузере после контролируемого переключения на новую версию: работающий VPN при подготовке пакета не останавливался и его настройки не изменялись.

Фактическая причина отсутствия IPv6 на стороне серверного маршрута этой проверкой не устанавливалась. Обработка указанного отказа не восстанавливает IPv6 на сервере. Для соединений без доступного имени сайта (включая некоторые случаи ECH), IPv6-only сайтов и UDP описанный TCP-повтор неприменим.

Если у профиля заданы только IPv6-адреса DNS и они тоже недоступны, DNS для повтора также не ответит. Системный DNS и другой провайдер автоматически не подставляются. Существующая защита от IPv6-трафика для профиля, в котором IPv6 вообще не настроен, сохранена.

Переключение правил по-прежнему пересоздаёт туннель. Отдельно найденная чувствительность сетевого монитора к смене временных IPv6-адресов в этот пакет не включена и не объявляется исправленной.

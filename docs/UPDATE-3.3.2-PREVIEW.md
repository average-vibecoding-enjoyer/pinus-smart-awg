# Pinus Smart AWG 3.3.2 Preview

Исправлен выбор DNS при прямом соединении с доменным именем. У исходящего соединения `direct` теперь явно задан `domain_resolver: direct-dns`. Ранее оно могло унаследовать DNS через AWG, хотя правило маршрутизации и доменное DNS-правило относили сервис к прямому трафику.

Это исправление затрагивает, в частности, отключённые переключатели VK и «Белые списки»: им по-прежнему соответствует прямой маршрут, а разрешение доменного имени теперь явно связано с прямым DNS.

## Проверка исправления

Регрессионный тест использует фактический JSON из `smart.BuildConfig` и настоящий код выбора резолвера, DNS-правил и соединения из движка. Фиктивные DNS-транспорты возвращают разные адреса из тестового диапазона для прямых и VPN-запросов; конечное соединение заменено на `net.Pipe`. Сокеты ОС, TUN, службы и сетевой монитор не запускаются.

Проверки прямых правил VK и российских сервисов прошли десять повторений: ответ получен через прямой DNS, запросов через VPN нет. Отдельный отрицательный контроль с удалённым `domain_resolver` воспроизвёл прежний дефект и завершился ожидаемым падением проверки. Это подтверждает конкретную ошибку выбора DNS, а не доступность сайтов в реальной сети.

Тесты клиента и `go vet` прошли. Девять синтетических конфигураций успешно проверены чистой командой движка `pinus-check`, без создания сети. Текущие результаты находятся в `evidence/direct-dns-regression.txt`, `evidence/direct-dns-regression-negative.txt`, `evidence/dnsfix-client-tests.txt`, `evidence/dnsfix-client-vet.txt`, `evidence/dnsfix-config-check.json` и `evidence/dnsfix-msi-metadata.json`. `release-manifest.json` содержит commit исходников и контрольные суммы бинарников.

## Что это не исправляет

Ошибка браузера `ERR_NETWORK_CHANGED` на пользовательском подключении не воспроизведена этой проверкой и не считается устранённой. Переключение маршрутизации по-прежнему пересоздаёт туннель; обновление правил без переподключения не реализовано. Пересоздание интерфейса может объяснять временную реакцию браузера на смену сети, но эта связь пока не подтверждена проверкой рабочего соединения.

Настройки продолжают применяться сразу, как в 3.3.1. Раздел «Управление» и обязательное ручное подтверждение не возвращались.

## Состав и границы сборки

Пересобран клиент. Движок AWG и Wintun побайтно совпадают с проверенными файлами 3.3.0; AWG 3.1 и старые конфиги сохранены. Полные исходники движка включены прежним отдельным архивом. Результаты его первоначальных проверок находятся в `evidence/inherited-3.3.0/` и явно отмечены как унаследованные.

Новый регрессионный тест DNS включён в исходники. Локальный `tests/directdns/go.work`, `go.work.sum` и временные результаты сборки в архив не включаются. Для запуска теста вне исходного рабочего каталога нужно поправить относительный `replace` движка, как описано в `tests/directdns/README.md`.

Подготовка пакета не запускает приложение, установщик или VPN. MSI только собирается и читается для проверки метаданных. Реальное переподключение, доступность VK, скорость, WFP при сбое и установка на чистой VM требуют отдельной проверки. Рабочие профили и сетевые настройки при подготовке обновления не изменяются.
